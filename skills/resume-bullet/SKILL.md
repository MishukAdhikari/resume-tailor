# Writing the bullet

Before drafting, read and apply [resume-evidence-gate](../resume-evidence-gate/SKILL.md).
Treat every worked example below as illustrative, never as a fact about the candidate.

## The formula

> **Result + Metric + Context**

- **Result**: what changed because of you. This leads the bullet.
- **Metric**: a specific, sourced outcome or scale figure, when available.
- **Context**: a brief explanation of how, or what you did.

Worked example, with the three parts marked:

> **Cut deployment failures** `Result` **by 40%** `Metric` **by consolidating two release
> paths into one** `Context`

The form it replaces:

> ~~Responsible for deployments~~

That names a duty and proves nothing. A duty says you were present. A result says
something is different because you were there.

## The first bullet is a gate, not an opening

Use the first bullet to make the strongest relevant case for reading further.

So: **the strongest sourced bullet relevant to the target role goes first**. Order the
rest by relevance and evidence, not by the size of the number alone.

## Verbs

### Vague openings, make the contribution specific

*Helped, Supported, Worked on, Assisted with, Was involved in, Participated in,
Responsible for.*

Replace vague openings with the action the candidate actually performed. Do not turn
assistance into leadership. "Supported" can be accurate when followed by specific scope
and evidence; name the actual work instead of automatically upgrading the verb.

### Ownership verbs, used precisely

*Built, Led, Designed, Delivered, Cut, Reduced, Shipped, Migrated, Owned.*

Each is a claim about authority, so each one has to be true at the level it asserts. Run
`resume-evidence-gate` before committing to one.

### Vary the openings

Vary openings when it improves readability. Repetition is an editing cue, not evidence
of AI authorship or inflated ownership. Accuracy takes priority over variety.

## Show soft skills, never name them

| Good | Bad |
| --- | --- |
| "Led a team of five" | "Leadership skills" |
| "Unblocked three stalled PR chains a week" | "Strong collaborator" |
| "Rewrote the on-call runbook after a Sev-1" | "Detail-oriented" |

A named soft skill is an assertion the reader has no reason to believe. A described one is
evidence. Soft skills live inside bullets and never in a skills list.

## When the metric does not exist

If the result is supported but no metric exists, use Result plus Context. For example:

> Cut provisioning failures on the rebuild path by consolidating three retry paths into one.

The qualitative result and the counts "three" and "one" still need evidence. If only the
work is known, describe the completed contribution without claiming an improvement.
Never estimate from a guess or add an activity count merely to fill the metric slot.
See `resume-evidence-gate`. The formula serves the honesty rule, not the other way around.

## Checklist for a single bullet

1. Does it lead with a supported result or concrete contribution?
2. If a metric is present, is it sourced and useful evidence of outcome or relevant scale?
3. Does the context explain the mechanism in one clause, not three?
4. Is the verb true at the level it claims?
5. Is it concise, specific, and natural when read alongside the other bullets?
6. Read aloud: what is the first follow-up question, and do you have the answer?
